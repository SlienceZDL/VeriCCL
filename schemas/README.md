These four JSON Schemas describe VeriCCL's standard input format: topology defines the topology, sketch defines the collective and budgets, atom defines synthesis strategies and hard constraints, and runtime defines the execution configuration. Field definitions come from vericcl/input/schema.py.

After structural validation, load_request checks collective semantics, M/S divisibility, rank mappings, budgets, and constraints across modules. The reader checks for duplicate JSON keys. JSON Schema covers file structure; cross-field validation and hardware capability measurement are handled separately.

Omitted or null fields receive defaults only when a default is defined. Required fields without defaults must be provided. S may initially be unspecified and is then determined by the capacity selection module; N is always derived from M/S. Integer inputs use the signed 64-bit range, with smaller upper bounds for specific runtime fields.

Compatibility forms are normalized before standard structural validation. Collective case variants and listed aliases remain supported. Supported legacy solver parameters move from hyperparameters to solver, and legacy strategy switches move from the atom top level to strategies. The legacy total_solve_timeout_s maps to the initial synthesis budget max_initial_synthesis_s. Providing the same setting in both old and new locations is an error. input_chunkup, N, force_resolve, force_recalibrate, and the three legacy synthesis boolean fields have been removed.

The value_sources section in run.json records whether each field came from an input file, a default, the command line, or a derived result. The command line can fill unspecified fields; changing a value specified in a file requires explicit --override-input. The input files remain unchanged.
