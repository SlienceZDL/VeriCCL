# V100 K<=16 experiment workflow

This workflow synthesizes and validates AllGather and AllReduce schedules for
the `v100-n2g4` and `v100-n2g8` topologies. The requested NCCL Tests message
sizes are 4 MiB, 16 MiB, 64 MiB, 256 MiB, 1 GiB, and 2 GiB. Run every command
from node2. The controller starts MPI on node4, and the hostfiles place the
node4 ranks before the node2 ranks.

The workflow uses existing GPU and Ethernet devices without changing GPU,
NIC, InfiniBand, route, interface, driver, CUDA, or OpenMPI configuration.
`/home/zdl/MSCCL/test` is a read-only baseline source. VeriCCL copies selected
XML files into the isolated experiment root before remote execution.

## Fixed paths

Set the experiment root and repository path on node2:

```bash
export VERICCL_EXPERIMENT_ROOT=/home/zdl/VeriCCL-experiments/2026-09-01-v100-k16
export VERICCL_REPO="$VERICCL_EXPERIMENT_ROOT/repo"
cd "$VERICCL_REPO"
```

The two hostfiles must have exactly these contents.

`$VERICCL_EXPERIMENT_ROOT/hostfile-2x4`:

```text
10.0.0.104 slots=4
10.0.0.102 slots=4
```

`$VERICCL_EXPERIMENT_ROOT/hostfile-2x8`:

```text
10.0.0.104 slots=8
10.0.0.102 slots=8
```

## Staged execution

First validate local paths, executable permissions, hostfile ordering, the
Ethernet contract, and non-interactive SSH access to node4:

```bash
.venv/bin/python -m vericcl.experiments.v100 preflight \
  --config "$VERICCL_EXPERIMENT_ROOT/config.json"
```

Run the 2-node, 1-GPU-per-node, 128 MiB K=1 smoke validation before the full
matrix:

```bash
.venv/bin/python -m vericcl.experiments.v100 smoke \
  --config "$VERICCL_EXPERIMENT_ROOT/config.json"
```

The smoke test uses full operator validation. Calibration points use one
correctness-enabled release process with five warmups and 20 measurements,
then one 20-iteration trace process. Trace iteration statistics determine
calibration stability and `B_link(k)`; final operator validation continues to
use rounds of 20 independent release processes.

Synthesize the 24 topology, collective, and size cases. Each case uses online
validation and verified tuning with a 10,800-second workflow budget. `--resume`
reuses only a passed output whose input and output hashes still match:

```bash
.venv/bin/python -m vericcl.experiments.v100 solve \
  --config "$VERICCL_EXPERIMENT_ROOT/config.json" --resume
```

Run exact-size VeriCCL measurements and all matching copied baseline XMLs:

```bash
.venv/bin/python -m vericcl.experiments.v100 benchmark \
  --config "$VERICCL_EXPERIMENT_ROOT/config.json" --resume
```

Generate CSV, JSON, and Markdown summaries:

```bash
.venv/bin/python -m vericcl.experiments.v100 summarize \
  --config "$VERICCL_EXPERIMENT_ROOT/config.json"
```

After preflight has passed, the complete sequence can be resumed with one
command:

```bash
.venv/bin/python -m vericcl.experiments.v100 all \
  --config "$VERICCL_EXPERIMENT_ROOT/config.json" --resume
```

To retry selected synthesis or performance cases, repeat `--case` with exact
IDs from `exp/v100-k16-manifest.json`:

```bash
.venv/bin/python -m vericcl.experiments.v100 solve \
  --config "$VERICCL_EXPERIMENT_ROOT/config.json" \
  --case v100-n2g4-ag-4m --case v100-n2g8-ar-2g --resume
```

## MPI and NCCL Tests contract

For 2x4, the command prefix is equivalent to:

```bash
/opt/openmpi-4.1.8/bin/mpirun --allow-run-as-root \
  --prefix /opt/openmpi-4.1.8 \
  -np 8 \
  --hostfile /home/zdl/VeriCCL-experiments/2026-09-01-v100-k16/hostfile-2x4 \
  -mca pml ob1 \
  -mca btl tcp,self,vader \
  -mca btl_vader_single_copy_mechanism none \
  -mca btl_tcp_if_include 10.0.0.0/24
```

For 2x8, only `-np` and `--hostfile` change to 16 and `hostfile-2x8`.
The controller invokes this prefix through node4, so node4 owns Rank 0-3 or
Rank 0-7. Rank traces are local files: node4 therefore generates the first
half and node2 generates the second half. The collector copies the node4 half
back to node2 before trace analysis; this is not a topology or Rank remapping.

Every VeriCCL XML is measured only at its exact message size with:

```text
-b SIZE -e SIZE -f 2 -g 1 -n 15
```

Each matching baseline XML is measured over the complete range with:

```text
-b 4M -e 2G -f 2 -g 1 -n 15
```

VeriCCL XML uses `NCCL_BUFFSIZE=2*slice_size_bytes`; baseline XML uses
`NCCL_BUFFSIZE=2097152`. Both use `NCCL_ALGO=MSCCL,RING`, Simple protocol,
Ethernet, and the same GPU visibility. Every run preserves `command.txt`,
`environment.json`, `stdout.log`, `stderr.log`, `measurements.json`, and
`activation.json`. Structured tables retain out-of-place and in-place values,
but performance conclusions use only in-place algorithm bandwidth.

MSCCL activation is confirmed only when the NCCL INFO marker is present and
the relative in-place/out-of-place bus bandwidth difference is at least 5%.
Unconfirmed measurements remain in raw artifacts but are excluded from the
comparison.

## Calibration and outputs

For slice size `S`, the measured maximum concurrency is:

```text
K_effective=min(16,max_calibration_channels,128MiB/S,link_max_channels)
```

No unmeasured concurrency is inferred. The 128 MiB calibration requires `S`
to divide 128 MiB. The solver then selects the best accepted K<=16 candidate;
the report does not claim global optimality unless `proven_optimal=true`.

Persistent state is stored in `$VERICCL_EXPERIMENT_ROOT/state.json`. Final
schedules and validation reports are under `runs/`, raw measurements are under
`performance/`, copied baseline provenance is under `baselines/index.json`,
and the final files are:

```text
summary/results.csv
summary/results.json
summary/report.md
```
